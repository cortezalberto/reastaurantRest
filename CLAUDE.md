## Project Architecture

This is a restaurant management system built with Java and following an object-oriented design pattern with the following key architectural components:

### Entity Layer (`src/main/java/org/example/entidades/`)
- **Base Entity Pattern**: All entities extend from `Base.java` which provides common fields (`id`, `nombre`, `eliminado`) and the abstract `getInfo()` method
- **Lombok Integration**: Heavy use of Lombok annotations (`@SuperBuilder`, `@Getter`, `@Setter`, etc.) for boilerplate code reduction
- **Bidirectional Relationships**: Entities maintain bidirectional relationships with proper `add` and `remove` methods

### Core Domain Entities
- **Company Structure**: `Empresa` -> `Sucursal` (Company -> Branch)
- **Product Catalog**: `Articulo` (abstract) -> `ArticuloInsumo` / `ArticuloManufacturado`
- **Order Management**: `Pedido` -> `DetallePedido` -> `Articulo`
- **Geographic Hierarchy**: `Pais` -> `Provincia` -> `Localidad` -> `Domicilio`
- **User Management**: `Usuario` -> `Cliente`
- **Categorization**: `Categoria` with support for subcategories
- **Promotions**: `Promocion` with time-based and type-based filtering

### Repository Pattern (`src/main/java/org/example/repositorio/`)
- **GenericRepository**: JPA-based repository implementation providing CRUD operations
- **EntityManager-Based**: Uses JPA EntityManager for database operations and transaction management
- **Database ID Generation**: Auto-incrementing IDs using `@GeneratedValue(strategy = GenerationType.IDENTITY)`
- **Key Methods**: `save()`, `findById()`, `findAll()`, `update()`, `deleteById()`, `findByField()`
- **Repository Instances**: Static repositories in Main.java for each entity type (Empresa, Sucursal, Cliente, etc.)
- **Transaction Management**: Automatic transaction handling with rollback on errors

### Key Design Patterns Used
1. **Builder Pattern**: Via Lombok's `@SuperBuilder` for complex object construction
2. **Repository Pattern**: For data access abstraction
3. **Template Method**: In the `Base` class with abstract `getInfo()` method
4. **Composition**: Extensive use of entity relationships

### Entity Relationships Overview
- **Empresa** contains multiple **Sucursal**
- **Sucursal** contains **Categoria** and **Promocion**
- **Categoria** contains **Articulo** and can have subcategories
- **ArticuloManufacturado** contains **ArticuloManufacturadoDetalle** (recipe ingredients)
- **Pedido** contains **DetallePedido** and references **Sucursal** and **Domicilio**
- **Cliente** has **Usuario** and multiple **Domicilio**

### Data Initialization
The `Main.java` class contains a comprehensive system initialization that creates:
- Geographic structure (countries, provinces, localities, addresses)
- Company and branch structure
- Product catalog with ingredients and manufactured items
- Categories with hierarchical organization
- Promotional campaigns with time restrictions
- Sample customers and users

The system demonstrates a complete restaurant management domain model suitable for handling orders, inventory, customer management, and multi-location operations.

## Critical Implementation Details

### Lombok Usage Patterns
All entities follow consistent Lombok patterns:
```java
@SuperBuilder              // For hierarchical builder pattern
@Getter @Setter           // Automatic getters/setters
@NoArgsConstructor        // Default constructor
@AllArgsConstructor       // Full constructor
@ToString(callSuper = true, exclude = {"collections"})  // String representation excluding circular references
```

### Base Class Implementation
- **Abstract Method**: All entities must implement `getInfo()` method
- **Common Fields**: `id` (Long), `nombre` (String), `eliminado` (boolean, defaults to false)
- **Soft Delete**: Uses `eliminado` flag instead of physical deletion

### Collection Management
- **HashSet Default**: Most entity collections use `@Builder.Default private Set<T> = new HashSet<>()`
- **Bidirectional Methods**: All entities with collections provide `add()` and `remove()` helper methods
- **ToString Exclusion**: Collections are excluded from `@ToString` to prevent circular references

### Repository Implementation Notes
- **Static EntityManagerFactory**: Shared across all repository instances via `Persistence.createEntityManagerFactory("restaurantePU")`
- **Generic Operations**: Single repository class handles all entity types through generics
- **Console Logging**: Prints entity class and assigned ID during save operations
- **Exception Handling**: All operations wrapped in try-catch with transaction rollback

### Entity State Management
- **Builder Pattern**: Use builders for object creation
- **Repository Persistence**: Use `save()` method for new entities, `update()` for modifications
- **Relationship Consistency**: Always use bidirectional add/remove methods

## JPA Configuration and Entity Management

- **Provider**: Hibernate JPA
- **Database**: H2 file-based database (`jdbc:h2:file:./restaurante_db`)

- **SQL Logging**: Enabled for debugging

### Entity Mapping Strategy
- **Inheritance**: Uses JPA JOINED strategy for `Articulo` hierarchy
- **ID Generation**: `@GeneratedValue(strategy = GenerationType.IDENTITY)` for all entities
- **Base Class**: `@MappedSuperclass` for common fields
- **Relationships**: Proper JPA annotations (`@OneToMany`, `@ManyToOne`, etc.)

### Transaction Management Pattern
All repository operations follow this pattern:
```java
EntityManager em = getEntityManager();
try {
    em.getTransaction().begin();
    // JPA operations
    em.getTransaction().commit();
    return result;
} catch (Exception e) {
    if (em.getTransaction().isActive()) {
        em.getTransaction().rollback();
    }
    throw new RuntimeException("Error message", e);
} finally {
    em.close();
}
```

## Data Initialization and System Flow

### Application Entry Point
The `Main.java` class orchestrates the complete system initialization in this specific order:

1. **Geographic Structure** (`crearEstructuraGeografica()`)
   - Creates and persists: Pais → Provincia → Localidad → Domicilio
   - **Critical**: Domicilio entities are persisted first and reused later

2. **Base Configuration** (`crearConfiguracionBaseConRepositorio()`)
   - Creates and persists: Usuario, Imagen, UnidadMedida entities
   - **Critical**: These entities are also reused in client creation

3. **Product Catalog** (`crearProductosYArticulosConRepositorio()`)
   - Creates and persists: ArticuloInsumo, ArticuloManufacturado with recipes

4. **Categories and Promotions** (`crearCategoriasConRepositorio()`, `crearPromocionesConRepositorio()`)
   - Creates categorization structure and promotional campaigns

5. **Company Structure** (`crearSucursalesConRepositorio()`)
   - Creates Sucursal entities that **reuse** already persisted Domicilio entities
   - Assigns categories and promotions to branches

6. **Client Management** (`crearClientesYPedidosConRepositorio()`)
   - Creates Cliente entities that **reuse** persisted Usuario, Imagen, and Domicilio entities

### Entity Construction Pattern
Always follow this pattern when creating entities:
```java
// 1. Use builder pattern for construction
Entity entity = Entity.builder()
    .field1(value1)
    .field2(value2)
    .build();

// 2. Persist immediately if it will be referenced
Entity savedEntity = repository.save(entity);

// 3. Use persisted entities for relationships
OtherEntity other = OtherEntity.builder()
    .relatedEntity(savedEntity) // Use persisted instance
    .build();

// 4. Maintain bidirectional relationships
parentEntity.addChild(savedEntity); // Uses helper method
```

## Troubleshooting Common Issues

### Build Issues
- **Compilation errors**: Ensure Lombok annotation processing is enabled
- **Missing dependencies**: Run `./gradlew clean build` to refresh dependencies

### Runtime Issues
- **EntityManagerFactory initialization**: Check persistence.xml configuration
- **Transaction issues**: Verify proper exception handling in repository operations
- **Relationship errors**: Ensure bidirectional helper methods are used

### Database Issues
- **Schema creation fails**: Delete `restaurante_db.mv.db` file and restart
- **Connection issues**: Verify H2 dependency in build.gradle
- **Performance**: Database recreated on each run (create-drop mode)

## Extension Guidelines

### Adding New Entities
1. Extend `Base` class for common fields and behavior
2. Use Lombok annotations consistently (`@SuperBuilder`, `@Getter`, `@Setter`)
3. Implement `getInfo()` method with meaningful description
4. Add bidirectional relationship helper methods
5. Create static repository instance in `Main.java`
6. Add to persistence.xml `<class>` declarations

### Modifying Existing Entities
1. Always test impact on existing data initialization
2. Update corresponding `getInfo()` implementations
3. Verify bidirectional relationship methods still work
4. Update demonstration methods in `Main.java` if needed

### Performance Considerations
- Use `FetchType.LAZY` for collections to avoid N+1 queries
- Consider adding indexes for frequently queried fields
- Monitor SQL output for optimization opportunities
- Repository operations are not optimized for bulk operations
